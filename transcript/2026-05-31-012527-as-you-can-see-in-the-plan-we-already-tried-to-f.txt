● I can see several concrete issues. Here's what's causing the slowness, in
  order of impact:

  ---
  1. depthEnabled: true — the biggest offender

  config.ts:239 has ar: { depthEnabled: true }. The ARCore Depth API runs a
  per-frame depth map computation using ML — it's extremely expensive on
  mid-range Android hardware and is the most common cause of "AR feels sluggish"
  reports with Viro. It should be false by default; you can offer it as a
  quality setting later.

  2. Plane detection never stops after placement

  PetARScene.tsx:103 — anchorDetectionTypes={[PLANE_ALIGNMENT]} is hardcoded and
  never cleared. Once the pet is placed, ARCore keeps scanning for new planes
  every frame for nothing. After placed, it should switch to
  anchorDetectionTypes={[]}.

  3. autofocus always on

  ARWalkScreen.tsx:215 — autofocus keeps the camera's hardware AF loop running
  continuously. It's useful while scanning, but once the pet is placed there's
  no reason for it. This drains both CPU and battery.

  4. Blinn lighting model on placeholder sphere (minor)

  arResources.ts:66 — lightingModel: 'Blinn' means the sphere is shaded with
  specular highlights per frame. For a placeholder, 'Constant' skips all
  lighting math and is essentially free.

  three files (config.ts, PetARScene.tsx, arResources.ts, ARWalkScreen.tsx). Fix
