# Database

PawStep uses `expo-sqlite` for all local persistence, with Drizzle ORM for type-safe queries and migration management. The database file is named `pawstep.db` and lives in the app's sandboxed storage directory. It is never readable by other apps and is not synced to iCloud or Google Drive by default.

---

## Opening the database

`src/db/client.ts` uses a lazy initialization pattern. The `db` export is a `Proxy` that delegates to a private `_db` variable which is `null` until `initDb()` is called:

```ts
// Lazily initialized — opened inside initDb() so module evaluation never throws.
let _db: ExpoSQLiteDatabase<typeof schema> | null = null;

export function getDb(): ExpoSQLiteDatabase<typeof schema> {
  if (!_db) throw new Error('getDb() called before initDb()');
  return _db;
}

// Proxy so existing `import { db }` call sites keep working.
export const db: ExpoSQLiteDatabase<typeof schema> = new Proxy(
  {} as ExpoSQLiteDatabase<typeof schema>,
  {
    get(_target, prop) {
      return getDb()[prop as keyof ExpoSQLiteDatabase<typeof schema>];
    },
  },
);
```

Import `db` from `@/db/client` wherever you need database access. Do not call `openDatabaseSync` directly.

`enableChangeListener: true` (set in `initDb()`) allows Drizzle to reactively re-run live queries when the underlying data changes.

**Important:** `initDb()` must be awaited in `App.tsx` before any repository function runs. Calling a repository before `initDb()` completes will throw `"getDb() called before initDb()"`.

`initDb()` also seeds a default pet row if none exists (the `seedDefaultPet()` function), so the Home screen always has something to display on first launch.

## Migrations

### How migrations run

`src/db/client.ts` exports `initDb()`, which applies pending migrations on app start:

```ts
import { migrate } from 'drizzle-orm/expo-sqlite/migrator';
import journal from './drizzle/meta/_journal.json';
import { m0000 } from './migrations';

const migrationFiles: Record<string, string> = {
  m0000,
};

export async function initDb(): Promise<void> {
  const expo = openDatabaseSync('pawstep.db', { enableChangeListener: true });
  _db = drizzle(expo, { schema });
  await migrate(_db, { journal, migrations: migrationFiles });
  await seedDefaultPet();
}
```

`initDb()` is a no-op for migrations that have already been applied — Drizzle tracks applied migrations internally.

### How `.sql` files are bundled

Metro cannot bundle `.sql` files natively. `babel-plugin-inline-import` (in `devDependencies`) does not work correctly with Metro's module system.

The actual solution: `npm run db:generate` runs Drizzle Kit and then `scripts/bundle-migrations.mjs`. The script reads each generated `.sql` file and writes its content as a TypeScript string export to `src/db/migrations.ts`. `client.ts` imports from `migrations.ts`, not from `.sql` files directly.

The migration key format is `m0000`, `m0001`, etc. — not the Drizzle-generated tag name (e.g. `'0000_third_brother_voodoo'`).

### Adding a new migration

1. Edit `src/db/schema.ts` — add or modify table definitions.
2. Run:
   ```bash
   npm run db:generate
   ```
   Drizzle Kit writes a new `.sql` file to `src/db/drizzle/`, updates `_journal.json`, and `bundle-migrations.mjs` automatically rewrites `src/db/migrations.ts` to include the new export.
3. Open `src/db/client.ts` and add the new export to `migrationFiles`:
   ```ts
   import { m0000, m0001 } from './migrations';

   const migrationFiles: Record<string, string> = {
     m0000,
     m0001,  // ← add
   };
   ```
4. Never modify or delete an existing migration file. Users who already have the app installed have already run those migrations.

## Schema reference

All table definitions live in `src/db/schema.ts`. That file is the single source of truth for the database shape.

### `pets`

One row per pet. Exactly one pet has `isActive = true` at any time.

| TypeScript name | SQL column      | Type               | Default    | Notes                                                          |
| --------------- | --------------- | ------------------ | ---------- | -------------------------------------------------------------- |
| `id`            | `id`            | `TEXT PRIMARY KEY` | —          | UUID generated by `src/utils/id.ts`                            |
| `name`          | `name`          | `TEXT NOT NULL`    | —          | User-chosen pet name                                           |
| `species`       | `species`       | `TEXT NOT NULL`    | —          | e.g. `'dog'` \| `'cat'` \| `'fox'`                            |
| `stage`         | `stage`         | `TEXT NOT NULL`    | `'baby'`   | `'baby'` \| `'child'` \| `'adult'` \| `'elder'`               |
| `stamina`       | `stamina`       | `INTEGER NOT NULL` | `50`       | 0–100; affects boss battle performance                         |
| `affection`     | `affection`     | `INTEGER NOT NULL` | `0`        | Accumulated affection points                                   |
| `growthValue`   | `growth_value`  | `INTEGER NOT NULL` | `0`        | Accumulated growth; drives stage transitions                   |
| `mood`          | `mood`          | `TEXT NOT NULL`    | `'normal'` | `'happy'` \| `'normal'` \| `'sad'` \| `'excited'`             |
| `isActive`      | `is_active`     | `INTEGER NOT NULL` | `false`    | Boolean; only one pet is active at a time                      |
| `createdAt`     | `created_at`    | `INTEGER NOT NULL` | —          | Unix milliseconds                                              |
| `updatedAt`     | `updated_at`    | `INTEGER NOT NULL` | —          | Unix milliseconds; required for future sync conflict resolution |

### `steps`

One row per calendar day. The step counter writes to this row throughout the day.

| TypeScript name  | SQL column        | Type               | Default | Notes                                                       |
| ---------------- | ----------------- | ------------------ | ------- | ----------------------------------------------------------- |
| `date`           | `date`            | `TEXT PRIMARY KEY` | —       | `'YYYY-MM-DD'` in local time; use `src/utils/date.ts`       |
| `stepCount`      | `step_count`      | `INTEGER NOT NULL` | `0`     | Total steps for the day                                     |
| `distanceM`      | `distance_m`      | `REAL NOT NULL`    | `0`     | Distance in metres                                          |
| `calories`       | `calories`        | `REAL NOT NULL`    | `0`     | Estimated calories burned                                   |
| `foodEarned`     | `food_earned`     | `INTEGER NOT NULL` | `0`     | Derived by `growthFormula.ts`; written back after calculation |
| `goal`           | `goal`            | `INTEGER NOT NULL` | `8000`  | User's daily step goal; snapshot at row creation            |
| `goalReachedAt`  | `goal_reached_at` | `INTEGER`          | `NULL`  | Unix ms when goal was first hit; `NULL` if not yet reached  |
| `updatedAt`      | `updated_at`      | `INTEGER NOT NULL` | —       | Unix milliseconds                                           |

### `progress`

A key-value store for cross-cutting game state: streaks, token balance, unlocked map IDs, and boss progress. Values are JSON-encoded strings.

| TypeScript name | SQL column   | Type               | Notes                                |
| --------------- | ------------ | ------------------ | ------------------------------------ |
| `key`           | `key`        | `TEXT PRIMARY KEY` | String key — see expected keys below |
| `value`         | `value`      | `TEXT NOT NULL`    | JSON-encoded value                   |
| `updatedAt`     | `updated_at` | `INTEGER NOT NULL` | Unix milliseconds                    |

#### Expected keys

| Key                | Value type            | Example                                        |
| ------------------ | --------------------- | ---------------------------------------------- |
| `streak_current`   | `number`              | `"7"`                                          |
| `streak_best`      | `number`              | `"14"`                                         |
| `tokens`           | `number`              | `"450"`                                        |
| `unlocked_map_ids` | `string[]`            | `'["map_park","map_river"]'`                   |
| `boss_progress`    | `Record<string, any>` | `'{"boss_1":{"attempts":2,"defeated":false}}'` |

These fields change frequently during early development. A KV table avoids a migration every time a new counter or flag is added. Once a field stabilizes, it can be migrated into a typed column in a later migration.

### `events`

Story, exploration, boss, and check-in events triggered during use. Each row is either pending (`resolved = false`) or dismissed by the user (`resolved = true`).

| TypeScript name | SQL column     | Type               | Default | Notes                                                   |
| --------------- | -------------- | ------------------ | ------- | ------------------------------------------------------- |
| `id`            | `id`           | `TEXT PRIMARY KEY` | —       | UUID                                                    |
| `type`          | `type`         | `TEXT NOT NULL`    | —       | `'exploration'` \| `'boss'` \| `'story'` \| `'checkin'` |
| `triggeredAt`   | `triggered_at` | `INTEGER NOT NULL` | —       | Unix ms when the event fired                            |
| `latitude`      | `latitude`     | `REAL`             | `NULL`  | GPS latitude; `NULL` for non-location events            |
| `longitude`     | `longitude`    | `REAL`             | `NULL`  | GPS longitude; `NULL` for non-location events           |
| `payload`       | `payload`      | `TEXT NOT NULL`    | —       | JSON object: dialogue lines, reward amounts, metadata   |
| `resolved`      | `resolved`     | `INTEGER NOT NULL` | `false` | Boolean; `false` = pending, `true` = dismissed by user  |

Index: `idx_events_type_time ON events(type, triggered_at)` — speeds up "show all unresolved exploration events in chronological order" queries.

---

### `equipment`

Cosmetic items owned by the user. `petId` is `null` when the item is in inventory (not equipped on any pet).

| TypeScript name | SQL column   | Type               | Notes                                                                                        |
| --------------- | ------------ | ------------------ | -------------------------------------------------------------------------------------------- |
| `id`            | `id`         | `TEXT PRIMARY KEY` | UUID                                                                                         |
| `catalogId`     | `catalog_id` | `TEXT NOT NULL`    | Matches a key in the hard-coded shop catalog in `src/game/tokens.ts`                         |
| `petId`         | `pet_id`     | `TEXT`             | FK → `pets.id`; `null` means unequipped; `ON DELETE SET NULL` unequips if the pet is deleted |
| `acquiredAt`    | `acquired_at`| `INTEGER NOT NULL` | Unix ms                                                                                      |
| `source`        | `source`     | `TEXT NOT NULL`    | `'token'` \| `'iap'` \| `'reward'`                                                           |
| `updatedAt`     | `updated_at` | `INTEGER NOT NULL` | Unix milliseconds                                                                            |

Index: `idx_equipment_pet ON equipment(pet_id)` — speeds up "show all items equipped on this pet" queries.

## Repository pattern

Each table has a corresponding file in `src/db/repositories/`. A repository:

- Imports `db` from `@/db/client` and operators (`eq`, `and`, etc.) from `drizzle-orm`
- Imports the relevant table and type from `@/db/schema`
- Exports named async functions — one per operation
- Never holds state; it is a thin query layer
- Is called from Zustand stores and custom hooks, never from screen components

### Type exports

`src/db/schema.ts` exports inferred types for every table. Use these in repository function signatures:

| Type name      | Derived from                    | Use for                          |
| -------------- | ------------------------------- | -------------------------------- |
| `Pet`          | `typeof pets.$inferSelect`      | Return type for select queries   |
| `NewPet`       | `typeof pets.$inferInsert`      | Parameter type for insert calls  |
| `StepDay`      | `typeof steps.$inferSelect`     | Return type for step row selects |
| `NewStepDay`   | `typeof steps.$inferInsert`     | Parameter type for step inserts  |
| `ProgressEntry`| `typeof progress.$inferSelect`  | KV row type                      |
| `Event`        | `typeof events.$inferSelect`    | Event row type                   |
| `NewEvent`     | `typeof events.$inferInsert`    | Parameter type for event inserts |
| `Equipment`    | `typeof equipment.$inferSelect` | Equipment row type               |
| `NewEquipment` | `typeof equipment.$inferInsert` | Parameter type for equipment inserts |

### Example — `pets` repository

```ts
// src/db/repositories/pets.ts
import { eq } from 'drizzle-orm';
import { db } from '@/db/client';
import { pets, type Pet, type NewPet } from '@/db/schema';

// Returns the currently active pet, or undefined if none exists.
export async function getActivePet(): Promise<Pet | undefined> {
  const result = await db.select().from(pets).where(eq(pets.isActive, true));
  return result[0];
}

// Inserts a new pet row.
export async function insertPet(pet: NewPet): Promise<void> {
  await db.insert(pets).values(pet);
}
```

## The `updatedAt` convention

Every table has an `updatedAt` column storing the current time as **unix milliseconds** (not seconds, not ISO strings).

Set `updatedAt` on every insert and every update. Use `src/utils/date.ts` to get the current unix ms timestamp.

This is not optional. The planned backend sync mechanism uses last-write-wins conflict resolution, and `updatedAt` is the timestamp it compares. A row missing `updatedAt` will not survive sync without a schema migration to add it.
